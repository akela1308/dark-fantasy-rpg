# «Мортис»: правила общей рабочей папки

Репозиторий находится в dark-fantasy-rpg внутри проекта Dark Fantasy. Перед работой прочитай docs/team/README.md, свой файл роли (если роль назначена) и ПРОДОЛЖИТЬ_CODEX.md. CLAUDE.md содержит исторические разделы: проверяй утверждения по коду.

## Правила владельца
- Рабочая ветка revision-2026-10. Не переключать общую ветку во время работы команды. Main и публикация требуют отдельного явного согласия Максима; push рабочей ветки разрешён.
- Не переписывать MapScene.js/BattleScene.js; новые системы в src/systems, интерфейсы в src/ui, данные в src/data/*.json.
- Не менять численный баланс без поручения. Готовый арт не перезаписывать: новая версия с новым номером. Соблюдать assets/generated/КАНОН_ОРУЖИЯ.md.
- В игровых текстах не использовать длинное тире, писать «ё», «здоровье», кавычки «ёлочки».
- Перед коммитом npm test, npm run build, npm run check:build. Визуальные изменения проверять в Chrome и скриншотами; анимации дополнительно в движении. Коммитить законченные шаги, только свои изменения.
- Не выдавать черновой арт за готовый. Решения владельца записывать в ВОПРОСЫ_МАКСИМУ.md, продолжать независимые части.
- Отвечать коротко по-русски. Сохранять workspace-write. Не трогать несвязанные программы и процессы; опасные системные действия требуют отдельного согласия на конкретную операцию. Правила владельца о безопасности компьютера и работе с 3D сохраняются; эта настройка их не отменяет.

## Команда
- Пять постоянных чатов описаны в docs/team/threads.json; роли в docs/team/roles/.
- В этой общей папке одновременно работает только один пишущий агент. Перед правками, установкой зависимостей, сборкой, изменением Git или созданием арта получить атомарную блокировку `.team-write-lock` по README. Чтение и независимые обсуждения можно выполнять параллельно.
- Блокировка является координационным соглашением, не технической песочницей. Не снимать чужую блокировку по таймеру, не откатывать чужие изменения, не использовать git reset --hard/git clean.
- Руководитель может распределять порученные Максимом задачи между созданными чатами через инструмент отправки сообщений. Специалисты отвечают в своём чате; руководитель читает итог через wait_threads/read_thread. Это не разрешение на письма, Slack или сообщения за пределами этой команды.
- Название роли не назначает другую модель и не даёт дополнительных полномочий. Не создавать бесконечные циклы взаимных сообщений и не обещать постоянную работу вне активной задачи.
